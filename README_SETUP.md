# 消耗品在庫管理アプリ（zaiko-shohin）— セットアップと使い方

よつば建設工業 社内向け。現場と事務所で軍手・溶接棒・ウエス・刃物などの消耗品在庫を管理し、
入出庫記録で在庫数が自動増減、最低在庫を下回ると警告するアプリです。

このアプリは **静的サイト（HTML/CSS/JS のみ・ビルド不要）** です。
データは **Firebase Firestore**、写真は **Firebase Storage** に保存し、全端末でリアルタイム同期します。

- 公開URL: https://nomurakougyouipad-oss.github.io/zaiko-shohin/
- Firebase プロジェクト: zaiko-shohin

---

## できること（画面と機能）

| 画面 | 内容 |
| --- | --- |
| 在庫一覧（PC） | KPI 4枚・検索・区分/保管場所フィルタ・並び替え・50件ページング・CSV出力 |
| 棚卸モード | 一覧で「数えた数」を入力 → 差異は「棚卸調整」履歴として自動記録 |
| 在庫一覧（スマホ） | 状態順カード表示（要発注→少ない→十分）／最近入出庫順・無限スクロール・FAB |
| 品目詳細 | 現物写真（撮影・アップロード）・指標6枚・入出庫履歴 |
| 入出庫記録 | ＋1/＋5/＋10ボタン・担当者プルダウン（前回記憶）・使った現場（任意）・記録後在庫のプレビュー |
| 発注アラート | 要発注リスト・発注推奨数・発注予定金額・CSV出力・「発注済」一括設定 |
| 設定 | 事務所/現場モード切替・現場マスタ・担当者マスタ・サンプルデータ投入 |

- 状態判定: `在庫 < 最低在庫 → 要発注（赤）` ／ `在庫 < 最低在庫×1.5 → 少ない（橙）` ／ それ以外 → 十分（緑）
- 発注推奨数 = `max(最低在庫×2 − 現在庫, 最低在庫)`
- 「発注済」の品目に入庫を記録すると、発注状況は自動で「未発注」に戻ります
- オフラインでも入出庫の記録は可能（Firestoreのオフライン永続化。復帰時に自動送信）。写真だけは電波が必要です
- 在庫金額は「今の単価 × 現在庫数」の概算表示です

## 初期セットアップ（Firebase コンソール）

Firebase プロジェクト `zaiko-shohin`（Firestore / Storage / 匿名認証）は作成済みです。
以下の3点が設定済みであることを確認してください。

### 1. Firestore ルール
Firebase コンソール **構築 → Firestore Database → ルール** に、同梱の **`firestore.rules`** の中身を貼り付けて **公開**。

### 2. Storage ルール
**構築 → Storage → ルール** に、同梱の **`storage.rules`** の中身を貼り付けて **公開**。

### 3. 承認済みドメイン
**Authentication → Settings → 承認済みドメイン** に `nomurakougyouipad-oss.github.io` を追加。

### このセキュリティ設計について（正直な注意）
- 匿名認証＋ルールにより、**未認証のアクセスや不正な形式のデータ書き込みは防げます**。
- ただし匿名トークンは誰でも取得できるため、これ**だけ**では「悪意ある第三者による書き込み」を完全には防げません。
- 社内・関係者限定の運用であればこの構成で十分実用的です。より堅くするなら、本番稼働後に
  **Firebase App Check（reCAPTCHA / App Attest）** の導入を推奨します。

## ローカルで動作確認する

ES モジュールを使うため、`index.html` のダブルクリックでは動きません。簡易サーバー経由で開いてください。

```bash
# Python がある場合
python -m http.server 5173
```

```bash
# Node.js がある場合
npx serve .
```

表示された URL（例: `http://localhost:5173`）をブラウザで開きます。
初回はデータが空です。**設定 → サンプルデータを投入** で動作確認用の8品目が登録できます。

## GitHub Pages で公開する

1. GitHub リポジトリ `zaiko-shohin` にこのフォルダ一式をプッシュ
2. リポジトリ **Settings → Pages** → Source: `Deploy from a branch`、Branch: `main` / `/(root)` で **Save**

## 日々の運用メモ

- **現場のスマホ**: 設定で「現場モード」に切り替えておくと、マスタ編集・発注操作のボタンが隠れて誤操作を防げます
- **担当者**: 設定 → 担当者マスタ に氏名を登録すると、入出庫記録がプルダウン選択になります（前回の人を記憶）
- **現場**: 設定 → 現場マスタ に現場名を登録すると、出庫時に「使った現場」を選べます（任意・空欄OK）
- **発注**: 発注アラートで「発注リストをCSV出力」→ Excelで開いて電話・FAX発注 → 「発注済」にする → 入荷の入庫記録で自動的に「未発注」へ戻る
- **棚卸**: 半年〜1年に1回、在庫一覧の「棚卸モード」で実物を数えて確定（差異は履歴に残ります）
- **在庫数がずれたとき**: 直接書き換えず、棚卸モードで修正してください（調整履歴が残ります）

## データ構造（Firestore）

- `items/{品目コード}` … 品名・型番・区分・現在庫・最低在庫・単位・単価・保管場所・棚番・仕入先・標準納期・写真URL・発注状況・最終入出庫日・最終棚卸日
- `logs/{自動ID}` … itemId・日時・区分（入庫/出庫/棚卸調整）・数量・記録後在庫・担当者・使った現場・メモ
- `sites/{自動ID}` … 現場名
- `persons/{自動ID}` … 担当者名

在庫数は入出庫履歴の積み上げを正とし、`items.stock` はキャッシュとして `increment()` で更新します
（複数端末の同時記録でも矛盾しません）。ずれは棚卸モードで補正します。
